## MLPerf source reconciliation

The CSV transcribes the official tables linked from the archived MLCommons
[v2.1 results](https://mlcommons.netlify.app/en/training-normal-21/) and
[v3.0 results](https://mlcommons.netlify.app/en/training-normal-30/) pages,
retrieved October 10, 2026. Times are minutes at the precision published in
those tables. Each row uses eight GPUs, so dividing the per-accelerator
normalized times yields the same ratio as dividing the server times.

| Workload | v2.1 result ID | v2.1 time (min) | v3.0 result ID | v3.0 time (min) | Ratio, rounded |
| --- | --- | ---: | --- | ---: | ---: |
| BERT | 2.1-2091 | 6.378 | 3.0-2064 | 5.469 | 1.166 |
| ResNet-50 v1.5 | 2.1-2091 | 14.746 | 3.0-2062 | 13.601 | 1.084 |
| 3D U-Net | 2.1-2091 | 13.101 | 3.0-2062 | 12.103 | 1.082 |

[NVIDIA's account](https://developer.nvidia.com/blog/breaking-mlperf-training-records-with-nvidia-h100-gpus/)
attributes these gains to software optimization and reports rounded gains
of 17%, 8.4%, and 8.2%, respectively. That attribution is distinct from the
published time comparison. The v2.1 preview system record names the GPU
model and count but omits clocks, host-memory capacity, and detailed software
versions. Matching the named GPU model does not independently establish
identical complete machines or isolate a compiler effect. Each row's CSV
metadata links both system descriptions.

The earlier A100 panel is excluded. Its NVIDIA blog source cites v2.0
partner results on different host configurations and, for several workloads,
80 GB A100 GPUs with a 500 W power limit, whereas the v0.7 NVIDIA results used
40 GB A100 GPUs at 400 W. Those comparisons cannot support an unchanged-hardware
software-gain claim. The chapter makes no cross-generation hardware comparison.

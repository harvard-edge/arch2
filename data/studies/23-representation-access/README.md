# Pair-level source accessibility in pinned RTL

This study extends the descriptive source analysis in `09-representation-dilation` by preserving every recovered declaration/use pair, matching token intervals to syntax paths on the exact same recoverable pairs, and reporting how pooled coverage changes under pair weighting versus equal file weighting. Its evidence is the public RTL source at six pinned commits. It contains no model evaluations or hardware experiments.

The primary result is sensitive to the sampling unit. For the 40,825 pairs with both measurements recoverable, a minimum source interval of 256 tokens contains 21.9% of pairs when every pair has equal weight, but 84.9% when every source file has equal weight and pairs are weighted equally within each file. At 1,024 tokens the respective values are 36.6% and 95.5%. The per-repository curves show the corpus variation. The large BaseJump `bsg_scatter_gather.sv` file contributes 16,464 of the 40,825 matched pairs (40.3%) and 16,044 of the 19,103 pairs whose minimum interval exceeds 4,096 tokens (84.0%). Omitting that file raises pair-weighted coverage from 21.9% to 36.5% at 256 tokens and from 36.6% to 60.8% at 1,024 tokens. These results describe this inherited convenience corpus and make its weighting sensitivity explicit; they do not estimate typical RTL.

## Measurement and units

A pair is one same-file signal declaration and a bound expression reference to it, as resolved by pyslang's name binding. Parameterized elaborations yielding the same source-position pair count once. The token index is the ordinal among non-trivia tokens in the file after preprocessing. `minimum_interval_tokens` is `abs(use_token_index - declaration_token_index) + 1`, the shortest contiguous interval of those tokens that includes both endpoints. The measured population includes bound source references in all conditional-generate branches in the parsed file, not only source from the branch selected for a particular top-level parameter value. The per-branch diagnostic for BaseJump `bsg_scatter_gather` records that `vec_size_lp` is set to 4 while the source visitor still yields bound pairs in branches 1 through 11. It is a source-layout measure, not a claim about instantiated hardware, prompt length, attention, retrieval, or model performance. A budget of 256 means the two endpoints could fit inside a 256-token interval if that interval were selected; surrounding prompt material is not included.

The syntax path is the number of edges between the declaration syntax node and the use-name syntax node in pyslang's concrete syntax tree. Syntax path edges and source tokens are separate units and are plotted on separate axes. The plotted matched set contains 40,825 pairs for which both values are recoverable. The pair CSV also retains all 40,995 token-measured pairs; 170 have no recoverable syntax path. Each row has repository and commit identity, path and file SHA-256, signal name, declaration/use byte offsets and line numbers, token indices and distance, minimum interval length, and an optional syntax path. Equal-file weighting selects uniformly among files with at least one matched pair, then uniformly among that file's matched pairs. `diagnostics/bsg_scatter_gather_generate_scope.json` retains the checked top parameter value, source hash and line locations, per-branch pair counts, and parser version.

The original 344-file list is inherited from study 09; its original selection rationale was not recorded. Two Ibex files have no module or interface declaration and remain in `derived/file_summary.csv` with exclusion reasons. Across measured files, 1,170 of 42,341 same-file signal-name reference syntax nodes were unbound under the selected pyslang compilation. The extractor counts a syntax node as bound when a corresponding `NamedValueExpression` resolves to a declared signal. A focused check confirmed that `vec_size_lp=4` is applied in `bsg_scatter_gather`, while the AST visitor still traverses bound references in conditional-generate source branches for values 1 through 11. This packet records unbound references as a parser coverage measure without assigning a cause to that status. Pair records include bound same-file pairs only. The parser uses the same file selection, repository-specific support files, preprocessing definitions, and required-parameter overrides documented in study 09. It does not imply cross-file references are absent from RTL as a whole: this analysis counts only same-file pairs.

## Reproduction

From the repository root, install the pinned environment and reproduce:

```sh
python3 -m venv .venv-representation-access
.venv-representation-access/bin/pip install -r data/studies/23-representation-access/requirements.txt
.venv-representation-access/bin/python data/studies/23-representation-access/reproduce.py
```

`collect.py` verifies each retained archive against `source_manifest.json`, then extracts it to the ignored `.cache/repos/` directory. It downloads an archive only if the retained copy is missing, using its pinned GitHub commit URL and checking the expected archive hash. `extract_pairs.py` is a study-local copy of the pyslang analysis logic used in study 09, adapted to emit pair rows and per-file denominator records. It does not modify study 09, the inherited manifest, or manuscript files. `summarize.py` computes the coverage curves and weighting sensitivities from the pair records; `diagnose_generate_scope.py` verifies the BaseJump example's top parameter value and records branch-level source counts; `plot_access.py` builds SVG, PDF, and 300-dpi PNG from the same pair CSV. The reusable dataset and summary are in `derived/pairs.csv`, `derived/file_summary.csv`, `derived/budget_coverage.csv`, and `derived/summary.json`.

PNG visual inspection is not asserted by `reproduce.py`; the separately versioned `visual_qa.json` applies only to the PNG hash it records.

## Attribution and scope

The pinned repositories and their authors own the RTL source. The upstream study `09-representation-dilation` owns the initial corpus selection, definitions, and file-level distance analysis; this study does not claim those as new. The new citable contribution is the retained pair-level dataset with source locations, the exact token/tree matched subset, minimum-interval coverage distributions, and pair-versus-file weighting sensitivity. The binding and tree traversal use the open-source pyslang frontend (version recorded in `derived/parser_version.txt`). Cite each upstream repository at the commit listed in `source_manifest.json` when reusing its source data, and cite this study folder and its `provenance.yml` when reusing the derived pair records or coverage analysis.

## Limits

The corpus is a convenience sample, not a representative sample of RTL styles. The inherited list includes small benchmark files and larger production files, and a single BaseJump file dominates the pair-weighted tail. Token distance depends on source organization and declaration style. Syntax-tree paths describe this parser's concrete syntax structure; fewer tree edges do not imply proportionally fewer model tokens or superior model performance. Binding and recoverability depend on elaboration choices and syntax-node availability. No experiment here measures model attention, retrieval, correctness, hardware behavior, or design quality.

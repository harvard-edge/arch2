## Source and scope

The [pinned repository](https://github.com/kaiming-cheng/kernelagent-optimization-artifacts/tree/56cf9183b527307538ccbe8f554a88502918d2d1) describes five curated KernelBench tasks on one H100. The measured quantity is the `time_ms` field in each retained `benchmark_results.json`. No README timing enters the plot. Round 1 is a proposed candidate, not the initial input kernel. Each plotted record is the source's kept kernel for its round. The step curves are a running minimum of those records, not a statement of what the source kept across rounds. RMSNorm's final kernel is closest to Round 3 by token comparison, while its lowest record is Round 8, as `summary.json` shows in `final_kernel_round`, `final_kernel_token_similarity`, and `best_round`.

The source publishes no timing distribution. The closest evidence is the starting time each task's four Round 1 workers report for what the trace layout indicates is one input kernel, and only one worker's files survive to support that reading. `summary.json` keeps these values and their spread, which runs from 1.00 to 1.40 times across the five tasks. The matrix-vector Round 5 step from its parent is 1.37 times, which lies inside the RMSNorm spread, so that step alone does not separate from noise. The two Round 5 workers that started from the Round 4 low are the stronger evidence of regression.

`attempts.csv` parses the attempt history in each round's `opt_prompt.txt`, a file the source keeps but this study did not retain until 2026-11-02. A round's attempts first appear in the next round's prompt, so the file covers rounds 1 to 7: 140 attempts, of which 139 have a time and one failed verification. In all 35 of those rounds the retained record is the fastest timed attempt, and `reproduce.py` asserts this. Round 8 attempts other than the retained one are not recoverable. The history keeps times, not the discarded kernels. These records do not establish a population success rate or an advantage over conventional search at matched cost.

The README cross-check found three disagreements beyond rounding. The transposed-convolution README gives 7.821 ms, whereas the best retained timing is 5.411904 ms. RMSNorm's README names Round 3 where the lowest record is Round 8. These may reflect different runs or measurement procedures; the artifacts do not establish the reason. `readme_crosscheck.json` preserves the discrepancy rather than resolving it by assumption. Treat this as an illustrative public record requiring an independent rerun before a performance claim becomes a centerpiece of the keynote.

## Reproduction

From the repository root, run `python3 data/run_study.py 10-kernelagent-search --expected 1 600 --reason "<why>" -- python3 reproduce.py` with an interpreter that has NumPy and Matplotlib, so that the attempt is logged. It checks source hashes, reconstructs `timings.csv` and `attempts.csv`, emits `summary.json`, and creates SVG, PDF, and 300 dpi PNG figures using the book's plotting helper. No GPU or network is needed. `collect.py` can fetch missing sources at the pinned revision. It verifies every downloaded Git blob against `source_tree.json`.

`source_manifest.json` records source URLs, bytes, hashes, and the collection interval. `build_receipt.json` records software versions, shared style hashes, source and output hashes, and checks performed. `runs.jsonl` logs attempts, but not completely: at least one run before logging began is unrecorded, and `provenance.yml` states the gap. Dependencies are Python, NumPy, Matplotlib, and Requests; exact build versions are in the receipt. GPU execution has not been repeated. The pinned tree contains no license file; review permission before redistributing the retained source code.
